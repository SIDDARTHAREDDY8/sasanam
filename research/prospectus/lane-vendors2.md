- **`NVIDIA-NeMo/Guardrails`** (7,202★, Apache-2.0 — verified `LICENSE-Apache-2.0.txt`, pushed 2026-09-26; note the old `NVIDIA/NeMo-Guardrails` path 301-redirects here) — **STEAL**. (2) **Input/output rail flow pattern** (`nemoguardrails/library/sensitive_data_detection/flows.co`): `flow detect sensitive data on input` → `$response = await DetectSensitiveDataAction(source="input", text=$user_message)` → `if $response.is_blocked … abort`; the same rail ships a `mask sensitive data on input` variant that *transforms* instead of blocking — detect→(mask|block) as two flows over one action, the exact seam shape for our authorized-channel exfil gap. (3) **Injection YARA bundle** (`nemoguardrails/library/injection_detection/yara_rules/`: `code.yara`, `sqli.yara`, `template.yara`, `xss.yara`) — complements the cisco-ai-defense YARA set from round 1; run at tool-input boundary. - **`nvidia/garak`** (9,366★, Apache-2.0, pushed 2026-09-16) — **STEAL** (attack-program tooling + evidence model). - **`protectai/llm-guard`** (3,210★, MIT — verified `LICENSE`, pushed 2026-07-08) — **STEAL** (scanner patterns; model weights stay on their side). Steal-worthy: (1) **Scanner protocol contract** (`llm_guard/input_scanners/base.py`): `scan(prompt) -> tuple[str, bool, float]` = (sanitized_text, is_valid, risk_score) — the three-tuple (transform, verdict, score) return contract; adopt for our policy-engine check functions. (2) **Vault placeholder pattern** (`llm_guard/vault.py` + `input_scanners/anonymize.py` + `output_scanners/deanonymize.py`): `Anonymize` replaces PII with placeholders stored in a `Vault`, `Deanonymize` restores them on output with exact/case-insensitive/fuzzy (`max_l_dist=3`) matching strategies (`output_scanners/deanonymize.py:18-118`) — the same sentinel-substitution shape as anthropics/sandbox-runtime from round 1, here as a reusable scanner pair; the fuzzy-match deanonymizer is the piece to copy for our Egress-Canary/sentinel handling. (3) **`InvisibleText` input scanner** (`llm_guard/input_scanners/invisible_text.py`): strips Unicode categories Cf/Co/Cn (zero-width/format chars), returns `(prompt, False, 1.0)` on hit — a 40-line portable covert-channel exfil check for our egress layer (complements Meta's HiddenASCIIScanner from round 1, which *decodes*; this one strips+flags). (4) **`FactualConsistency` output scanner** (`llm_guard/output_scanners/factual_consistency.py`): NLI entailment between prompt and output with `minimum_score=0.75` — the cheap-tier factual-poisoning check. Bonus: `benchmarks/run.py` + `input_examples.json`/`output_examples.json` — the per-scanner benchmark harness shape for our safeguard benchmark.

## Cross-lane notes

- **OTel is now the missing schema layer.** Round 1 noted "policy verdicts as first-class trace spans" (openai-agents-python) and "sell decision reconstruction" (AGT Decision BOM) — `semantic-conventions-genai` gives both a standard vocabulary. Aligning our audit log fields to `gen_ai.agent.*` / `gen_ai.tool.*` is a one-time rename with compounding interop payoff (any OTel-native auditor tooling reads our evidence).
- **Guardrail-catalog convergence:** NeMo's `RailManifest` (categories × capabilities) and llm-guard's `Scanner` protocol are the same idea at different altitudes — a *registry of typed checks with declared direction and capability*. Our policy-engine check registry should be designed as this from day one.
- **Keyless signing changes the anchoring math:** sigstore-python's OIDC-bound `sign_dsse` removes the key-custody objection to signing every attestation bundle — K-060 external anchoring gets cheaper than our current KMS-adapter path for the evidence pipeline (engine keys still need the KMS workstream).
