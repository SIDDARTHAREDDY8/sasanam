## Headline

**The witness layer is production-grade and composes — Sasanam's existing `gov/witness_consistency.py` already speaks its wire format.** A live Rekor v2 production checkpoint was captured this wave carrying three synchronous witness cosignatures timestamped the same second as the fetch: the checkpoint is a C2SP signed note (`text/plain; charset=utf-8`, `cache-control: no-cache`, served from GCS — untrusted storage), cosignatures are Ed25519 `cosignature/v1` 76-byte lines (`keyID(4) || u64BE timestamp(8) || sig(64)`), and the specs' MUST-ignore-unknown-signatures rule makes key rotation and cosigning compose with zero protocol change. **The greenfield is exactly two artifacts:** (1) the *signed witness-policy artifact* — no deployed standard exists (Sigstore's TUF-signed TrustedRoot has no witness-key field despite spec prose referencing one; witness-network.org lists are unsigned and pre-production), and (2) the *fail-closed monitor loop* — the MarkovianProtocol/log-monitor exemplar's three-conjunct head gate is the shape to adapt. Client-to-client gossip SKIP is confirmed 13 years on (RFC 6962, 2013): zero production deployments in any surveyed ecosystem; the substitute is witness cosigning + independent monitors + governance (log-list state machine).

## 1. Witness checkpoint publication

**Bottom line (from `inputs/witness_publication.md`):** publish byte-for-byte C2SP. The production shape is proven at 137M+ entries; the only invention is the signed witness-policy artifact.

- **Static endpoint shape — STEAL.** `GET <prefix>/checkpoint`, `text/plain; charset=utf-8`, `cache-control: no-cache` + etag, object-store-backed static file. Live capture (`log2025-1.rekor.sigstore.dev/api/v2/checkpoint`, tree 137,219,218): GCS headers (`x-goog-*`, `server: UploadServer`), `access-control-allow-origin: *`, no redirect hop. C2SP `static-ct-api` v1.1.0: "headers SHOULD prevent caching beyond a few seconds"; origin line is the schema-less submission prefix, never assumed reachable. (Go sumdb's `/latest` deviation: SKIP, non-canonical.)
- **Signed-note format — STEAL.** 3-line checkpoint body (origin, decimal tree size, base64 RFC 6962 root); em-dash `—` signature lines; `keyID = SHA-256(name || 0x0A || type || pubkey)[:4]`; verifiers MUST accept ≥16 signatures and MUST ignore unknown ones — *this is the rotation/cosigning enabler*. Log's own line is plain `0x01` Ed25519 (68 bytes); witness lines are `0x04` timestamped cosignatures (76 bytes). Witness operators visible on the live production checkpoint: Geomys (`witness.navigli.sunlight.geomys.org`), stagemole.eu, Google (`staging.witness.transparency.goog/ring-any-bells` — "staging" prefix on the production log is unexplained; see Open questions).
- **Cosignature semantics — STEAL.** Ed25519 `cosignature/v1` signs `cosignature/v1\ntime <ts>\n<origin>\n<size>\n<root hash>\n` — domain-separated, timestamp-bound; "as of the specified time, the consistent tree head with the largest size the cosigner has observed". ML-DSA-44 `subtree/v1` is spec'd and recommended for new deployments (Tessera MTC uses it) — WATCH for Sasanam v2; v1 ships Ed25519.
- **vkey pin format — STEAL.** `<name>+<hex keyID>+base64(sigType || pubkey)` — name, key ID, and key material in one auditable line. Pin the full (name, keyID) tuple; keying on name alone breaks on rotation.
- **Witness-set pinning — ADAPT, the greenfield piece.** No one ships a signed witness-policy artifact yet. Witness-network.org `logs/v0` line grammar (vkey/origin/qpd/contact) is the right *shape* but unsigned and pre-production ("production list: not available yet"). Sigstore TrustedRoot-over-TUF is the right *distribution* (5-keyholder threshold ceremony, validity-windowed instances) but has no witness-key slot. Chrome CT's log lifecycle (Qualified/Usable/ReadOnly/Retired, `previous_operators` time-bounded attribution) is the right *retirement semantics*. Design: TUF-style signed document, entries = vkeys + operator identity + validity window, versioned, threshold-signed root, **overlap-then-retire** rotation (keep old instances, accept overlapping windows, accept a future-dated successor — the trustroot.proto contract). Bilateral/operator-local configs (Tessera `WithWitnesses`, ArmoredWitness) are the deployed fallback: WATCH.
- **Key rotation — rotation is non-breaking by construction, if the verifier implements MUST-ignore.** What breaks: verifiers rejecting notes with unknown signature lines; pinning by name instead of vkey tuple; trust roots that drop old instances; non-overlapping validity windows (verification gaps); witness sets pinned without validity windows (a rotated witness key looks like an unknown cosigner → fail-closed quorum loss — plan the overlap). Witness state loss is the sharp edge: a witness MUST persist-before-respond and MUST NOT resume cosigning from the log's current head after losing state (destroys the anti-equivocation guarantee). Rekor v2 rotates via yearly shards discovered over TUF (live: `log2025-1`, Ed25519, valid from 2025-09-23). **Build-lane test to pin:** feed a checkpoint with an unknown-key line and assert it still verifies.

## 2. Fail-closed monitor loop

**Bottom line (from `inputs/monitor_loop.md`):** adapt MarkovianProtocol/log-monitor (Apache-2.0, 676-line Python, hourly cron). Its exact head-advancement gate, alert ordering, and atomic-state discipline are the production shape; its missing-fringe silent non-advance edge is the one bug to fix, not copy.

- **Head-advancement gate — STEAL.** `if authenticated and not tree_bad and leaf_verified:` — authenticated = log Ed25519 sig + *verified* pinned-witness cosigs ≥ quorum (default 4; a pinned witness whose cosignature fails to verify is itself a forgery-signal alert); tree_bad = failed RFC 6962 proof / tree shrink / same-size-different-root (equivocation); leaf_verified = recomputed root from served leaves equals the signed root. Any failure leaves the head unchanged and re-alerts. **Staleness is alert-only** (3h freshness bound vs hourly cosigning) — it does NOT block advancement in the exemplar; Sasanam must decide explicitly whether a stale checkpoint blocks advancement (costlier) or only alerts, and budget either way.
- **Leaf recomputation — ADAPT.** Incremental Merkle fringe persisted in `state.json`; steady-state fetches only `[old_size, size)` in ≤256-leaf batches via `GET /leaves`, strict batch-size rejection ("a mis-sized batch silently mis-indexes every later leaf"); `--init` refuses to baseline unless the recomputed root matches the authenticated checkpoint. The explicit threat model: the leaf plane is unauthenticated JSON — the leaf↔root check is what caught the Yeti 2022 bit-flip. Adapt batch sizes to Sasanam's leaves.
- **Alert discipline — STEAL.** Auth/consistency alerts fire *before* the leaf endpoint is touched (a hostile leaf plane must never mute a fork alarm). Checkpoint-fetch failures alert from the 3rd consecutive failure, every run while down. Daily heartbeat email so silence is itself a signal. Atomic state (`state.json.tmp` + fsync + `os.replace`, `.bak` of prior); missing/corrupt state is a **hard stop, never a silent re-baseline**.
- **Advisory witnesses — ADAPT.** Cosignatures verified and reported but never counted toward quorum unless promoted via a new signed trust-root manifest — "keeps the monitor's arithmetic equal to the log's published policy."
- **PQ cosignatures — WATCH.** Dual-implementation cross-check (agree-or-invalid, never silent pass); adopt when Sasanam pins non-Ed25519 cosignatures.
- **The edge to fix:** if state has no fringe but the log grew, `leaf_verified` stays False and the head **silently never advances again** — no alert fires. The build lane must backfill the fringe or alert on `fr is None` (upstream fix status unverified).
- **Availability cost of fail-closed — budget explicitly.** Rekor v2 already runs fail-closed in production: synchronous witnessing *blocks* checkpoint publication until witnesses cosign; documented mitigations are ≥20s client timeouts and increased checkpoint intervals (rekor-tiles CLIENTS.md) — the industry's precedent for the cost. Tessera today defaults `WitnessOptions{FailOpen: true}` ("eventually fail closed by default" per summit-2025 slides), so a fail-closed monitor's head freezes while the log keeps moving — the divergence lands entirely on the verifier side. Sasanam is fail-closed on both sides: during any witness outage or quorum shortfall the trusted head freezes, every newer checkpoint refuses, and hourly re-alerts fire. Budget: alert volume, the divergence window (newly appended records unverifiable-by-policy), and the explicit staleness-block vs alert-only decision. Sigstore reference availability: 99.5% SLO with public status page and round-the-clock pager.
- **Incident corpus.** Yeti 2022: single-bit hash corruption; third-party monitors' consistency checks failed from late June 2022; shard set read-only and decommissioned. DigiCert Mar-2025 CoE (Nessie/Yeti/Wyvern/Sphinx): IOPS starvation, MMDs missed by *days*, three shards retired — a frozen-checkpoint event at production scale, and exactly what the staleness alert is the tripwire for. **No production incident found of a fail-closed witness-quorum monitor halting on unreachable witnesses** — that incident record does not exist yet.
- **Who runs independent monitors (2026):** CT — crt.sh (Sectigo, first-party confirmed), Cert Spotter (SSLMate), Cloudflare, DigiCert, Censys, Hardenize, Report-URI (NDSS'24 census); Sigstore/Go — gdbelvin/kt-witness independently witnesses Rekor v2 production and the Go sumdb (fork negative-control refused as `ForkError`).

## 3. Gossip reality check — SKIP CONFIRMED

**Bottom line (from `inputs/gossip_reality.md`):** the w320 SKIP-gossip verdict holds. Zero production client-to-client checkpoint gossip in any 2026 ecosystem surveyed.

- CT: `draft-ietf-trans-gossip` expired at -05, never an RFC. Chrome never gossips STHs between clients — it does k-anonymous SCT auditing (20-bit prefix, 0.01% sampling, client→Google, deployed March 2021). CT-over-DNS shipped as client→Google fetch, not gossip; draft expired. The only production "pollination" is sslmate/ct-honeybee (2017–2025, CC0) — log→auditor, operator-run, not client-to-client.
- Sigstore: Rekor v2 has no gossip endpoints; spec mandates offline verification (§4.1) and removed the v1 search API (§4.5); split-view answer is C2SP tlog-witness cosigning ("only logs and sometimes monitors communicate directly with witnesses"). Nuance on w320's wording: a tile *read* API still exists but the spec deprecates its use for verification — "removed all online verification APIs" is slightly overstated; the substantive claim holds.
- Go sumdb: anti-gossip by construction (design doc: clients keep local STH timelines, fail the build on inconsistency; tiles are static and servable by anyone). npm/PyPI delegate to Sigstore bundles. Firefox CT-enforced since 135 (Feb 2025), no gossip. Android Pixel BT checkpoints carry ArmoredWitness cosignatures — witness-cosigning, not gossip. Google Key Transparency's own design doc: "gossip model… has not been fully designed." CONIKS never left prototype.
- **The production substitute, documented precisely:** independent monitors (crt.sh, Cert Spotter — which caught the Yeti-2022 bit-flip by recomputing the root from 65.5M entries — Cloudflare) + out-of-band comparison on ct-policy@chromium.org + governance via the log-list state machine (Usable → Retired → Rejected; concrete disqualifications: DigiCert Yeti2024 Retired→Rejected, Yeti 2022 decommission, seven 2016–2020 failures, all with zero user impact). Chrome removed the RFC 6962-log SCT requirement (Apr 15, 2026; Chrome 144) — SCTs may now come exclusively from static-ct-api logs.
- Adjacent: ADAPT Chrome's k-anonymous SCT auditing (privacy-preserving omission detection); WATCH ArmoredWitness (Apache-2.0, operational across Go/Sigstore/Pixel BT) and ct-honeybee (CC0).

## 4. Offline auditor + witness artifacts

**Bottom line (from `inputs/offline_witness.md`):** the minimal set is seven artifacts; only the trust root must be pre-provisioned; C2SP was built for offline policy ("no URLs are required if the policy is used only for offline verification", `tlog-policy.md`). The sharp problems are freshness without network and stale-policy detection across a one-way gap.

- **Minimal verifiable set:** (1) the checkpoint note itself (body + log sig line + all witness cosignature lines) — EMBED; (2) log public key as a full vkey (name + keyID + 32-byte key; a key ID alone is a 4-byte hint and cannot authenticate) — EMBED, trust from policy; (3) witness public keys, full vkeys for every carried cosigner — EMBED, trust from policy; (4) signed witness-policy artifact (known logs/witnesses by public key, quorum rule — mandatory per `tlog-policy.md`, monotonic version, expiry) — EMBED, authenticated by a policy-signing key PINNED in the auditor's trust root; (5) consistency proof from the auditor's last-trusted head to the new checkpoint (RFC 6962-shaped; Sasanam has this) — EMBED (or the full signed checkpoint chain back to the genesis anchor if no prior head); (6) inclusion proofs for entries of interest — EMBED (`tlog-policy.md` explicitly scopes these as "information needed for additional steps required by an offline verifier"); (7) cosignature `time` lines — EMBED (they ride in the note; the auditor's only witness-clock agreement signal). **Hard rule: everything may be embedded except the trust root itself.**
- **Precedents — STEAL:** cosign/Sigstore air-gap contract (bundle carries all verification material; pinned `trusted_root.json` is the sole pre-provisioned artifact; operator owns refresh — README is blunt about this); Sigsum (designed so "a malicious log operator is unable to fool even an offline verifier"; policy file = logs + witnesses + quorum by public key — the direct template for our signed witness-policy artifact); in-toto offline layout (embed functionary keys, pin the owner's key). SKIP: CT as an offline model (no air-gap story exists); cosign's deprecated `--offline` flag pairing.
- **Freshness without network:** three checks — each cosignature's `time` vs the auditor's clock (reject future, per spec's MAY); `auditor_now − max(cosignature times)` ≤ policy max-staleness (C2SP defines **no** bound — the bound is our policy addition); quorum timestamp clustering (a served-stale checkpoint shows old witness times against a recency-expecting policy). Wrong clock breaks TUF-style freeze detection (clock ahead) or false-rejects (clock behind). An adversary controlling the crossing medium serves a frozen old-but-validly-signed checkpoint — the only defenses are the policy staleness bound against a trustworthy clock and quorum agreement. **The sign-then-cross ceremony must bind a freshness statement into the exported root-of-trust (the QR checkpoint), not just a hash.**
- **Stale policy across a one-way gap:** TUF's rollback (N+1) and expiry semantics adapted with a persisted last-seen version watermark on the auditor side — there is no in-band "superseded" signal; the crossing ceremony IS the freshness channel. Keep expiries short to bound the superseded-but-unexpired window.

## Direction brief for the wave-322 build lanes — ordered by risk

1. **Signed witness-policy artifact (greenfield, highest risk — everything else depends on it).** TUF-style signed document; entries = vkeys + operator identity + validity window; versioned; threshold-signed root; overlap-then-retire rotation (keep old instances, accept overlapping windows, accept future-dated successor); Chrome-style lifecycle states (Qualified/Usable/ReadOnly/Retired) for graceful degradation; N+1 rollback + short expiry for the offline case. Templates: Sigsum policy file (BSD-2-Clause), Sigstore TrustedRoot-over-TUF ceremony (add the missing witness-key slot), witness-network `logs/v0` line grammar (sign what is upstream unsigned). Acceptance: a client holding only the policy artifact verifies a fresh checkpoint with zero log calls.
2. **Witness checkpoint publication (low invention risk — wire format is byte-for-byte C2SP).** `GET /checkpoint`, `text/plain; charset=utf-8`, `cache-control: no-cache` + etag, object-store-backed static file; 3-line body; Ed25519 `0x01` log signature + `0x04` timestamped cosignatures; MUST-ignore-unknown-signatures; vkey pins. Collection path: log→witness `POST add-checkpoint` (old size + ≤63 consistency-proof lines + checkpoint; 409/422 semantics; persist-before-respond atomicity). Pin the rotation/cosigning tests: unknown-key line still verifies; name-vs-vkey-tuple pinning; witness state-loss must not re-baseline. Fail-closed where upstream is fail-open (Tessera `FailOpen: true` today) — treat witness unavailability as a policy decision, not a default.
3. **Fail-closed monitor loop (adapt, don't invent).** The three-conjunct gate (`authenticated and not tree_bad and leaf_verified`); alert-before-leaves ordering; incremental Merkle fringe with strict batch-size rejection; atomic state + hard stop on missing/corrupt state; 3h-freshness alerting + daily heartbeat; advisory-witness bookkeeping. **Fix, don't copy:** the missing-fringe silent non-advance edge (backfill or alert). Decide staleness-block vs alert-only explicitly and budget the availability cost (Rekor v2's ≥20s timeouts + longer checkpoint intervals are the industry's answer for the signing path; no documented precedent exists yet for a monitor refusing to advance).
4. **Offline export witness layer (procedure + small tooling).** Seven-artifact export (checkpoint note, full vkeys, signed policy, consistency proof chain, entry inclusion proofs, cosignature times); trust root pre-provisioned only; QR carries the cosigned checkpoint (~200–500 bytes) as the root of trust with a freshness statement, never the payload; TUF-adapted version watermark for stale-policy detection; SEC 17a-4-vocabulary runbook (prompt, legible, true, complete). Acceptance: an auditor with the QR + the file verifies the bundle offline with no network.

**Cross-cutting design rules (from the research):**
- The registry/CDN is untrusted storage. Checkpoint bytes, cosignature lines, and proofs verify client-side against the policy artifact, always.
- MUST-ignore-unknown-signatures is the rotation protocol — never "helpfully" reject notes with extra lines.
- Pin the (name, keyID) vkey tuple, never the name alone.
- Fail-closed is stricter than production (Tessera today, CT monitors historically) — budget the availability cost in the runbook, explicitly: alert volume, divergence window, staleness policy.
- No gossip protocol. The substitute is witness cosigning + independent monitors + governance (log-list state machine). Do not build STH gossip.
- QR = root of trust (with freshness statement), never payload.
