## 1. CVE-2026-92574 — CRI-O checkpoint restore bypasses destination security context (NEW, 2026-09-21)

cvefeed.io (updated 1 day ago): a vulnerability in CRI-O checkpoint
restore lets a user who can create a pod from a malicious checkpointed
container bypass the *destination* Kubernetes security context — the
restored process may **retain credentials, Linux capabilities,
no_new_privs, and seccomp state from the checkpoint** instead of
enforcing the destination configuration. CVSS 9.4-ish profile
(C:H/I:H/A:H per the feed's V3.1 line), CWE-250. Affects CRI-O 1.34+ /
OCP 4.17+; fixes applied to branches, not yet released.

Wave-60 read: this is a *security-state inheritance* bug — the exact
class our sandbox avoids by installing the seccomp filter fresh in
`preexec` (`_install_seccomp_filter_for_mode` after
`PR_SET_NO_NEW_PRIVS`, never inherited from a checkpoint or parent
image). We do no checkpoint/restore anywhere in `gov/`, so there is
no reachable surface — **boundary note, not a finding**. It does
reinforce the D2 privileged-CI spec (F81_WALL_READINESS.md): the
kernel-loaded filter must be verified as *installed at launch*, not
assumed from image/config state.
