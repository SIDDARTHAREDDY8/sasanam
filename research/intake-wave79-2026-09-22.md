## What was learned (and what wave-79 claims vs does not claim)

- Willison's lethal trifecta (June 2025): private data + untrusted
  content + external communication in one session = one crafted page
  away from exfiltration. Documented exploits span M365 Copilot,
  GitHub MCP server, GitLab Duo, ChatGPT, Amazon Q, Slack (Apr 2023–
  Feb 2025). His stated mitigation is structural: never let one agent
  hold all three at once.
- Meta's "Agents Rule of Two" (Oct 2025): at most two of
  {untrustworthy input, sensitive systems/data, state-change/external
  comm} per run; the third needs a human or a fresh privilege-stripped
  context. Willison calls it the best practical advice for secure
  agent systems.
- The public lethal-trifecta-audit skill (opened above) does leg
  classification per tool, computes closure *transitively across
  tools* ("the legs combine transitively across tools — they do not
  need to be the same tool, or even the same MCP server"), and treats
  the leg-3 human approval gate as the clause that decides most
  setups: "Nearly every useful agent carries all three legs; what
  separates a safe setup from an exposed one is whether egress is
  auto-approved." Its fix ordering is to cut the cheapest leg —
  usually gating egress.
- Wave-79's invention claim is bounded: the three axes and the
  trifecta are prior art (Willison; NIST-adjacent framing). What the
  wave built is the *policy primitive + enforcement wiring*: a closed
  TOOL_AXES registry, tier computed over effective grants (role ∪
  verified delegation scope ∪ lease scope), a policy-independent
  approval floor on external-comm tools that only overrides allow,
  and the reserved `trifecta-tier-floor` sentinel. This matches the
  audit skill's "gate leg 3" fix direction but implements it as a
  runtime floor rather than a config audit.
- NIST AI RMF (Govern/Map/Measure/Manage): agent-governance
  crosswalks treat policy as executable code under version control
  with every agent→tool call traced with `policy_version` and
  decision reason — the same totality direction as wave-79's
  policy_version + matched_rules stamping, and the same reason the
  provenance validator refuses field-less records.
- One honest divergence noted: the public audit framing computes
  closure over a session's *reachable tools*; wave-79 computes the
  tier over *effective grants* (role tools ∪ delegation scope ∪ lease
  scope), which is strictly wider (a delegated or leased tool adds
  axes the role alone lacks). The wave-79 probes cover this with the
  cross-hop composition situation.
