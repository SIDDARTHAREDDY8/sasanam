## Findings (from search snippets, not opened pages)

1. **CVE-2026-64564 ("SCTPhantom") — SCTP UAF → container escape,
   Linux ~6.x, disclosed ~2026-09.** Tencent security researchers
   report a use-after-free in the Linux kernel SCTP implementation
   exploited for container escape, demonstrated at 6/8 attempts with
   the *default* seccomp profile active. The researchers' stated
   exposure factors explicitly include "the availability of SCTP,
   **access to raw and packet sockets, the user namespace policy, the
   seccomp configuration**, the Linux capabilities, and the Linux
   Security Module policies" (emphasis added). Affected: kernels with
   the SCTP module; patches pending at disclosure time.
   Relevance: the wave-58 draft left the `socket()` protocol argument
   unconstrained — `socket(AF_INET, SOCK_STREAM, 132)` (SCTP) would
   have passed the cage filter. Wave-59 hardened this same-wave: the
   protocol arg rule allows only {0, IPPROTO_TCP}, denying SCTP (132),
   DCCP (33), and any other protocol smuggling through SOCK_STREAM —
   defense-in-depth (kernel exploits are outside this layer's threat
   model), not a finding. See `workstreams/evals/SECCOMP_REPORT.md` §3.
2. **CVE-2026-31431 ("Copy Fail") — AF_ALG page-cache write,
   disclosed ~2026-09.** A 4-byte page-cache overwrite via `algif_aead`
   sockets ("Copy Fail") reportedly escapes container isolation.
   Reported mitigation: "drop a custom seccomp profile **blocking
   AF_ALG**" because "runtime-default seccomp does not stop it".
   Relevance: the cage filter's domain allowlist (AF_UNIX/AF_INET only)
   denies AF_ALG (38) at the `socket()` call — validates the positive
   allowlist shape as defense-in-depth. No action taken.
3. **CVE-2026-92574 — CRI-O checkpoint restore bypassing security
   contexts.** Checkpoint/restore may retain credentials, capabilities,
   `no_new_privs`, and seccomp state while bypassing destination
   configuration. Relevance: deployment-hygiene boundary note — our
   filter installs fresh per child (`_harden_worker`, post
   `NO_NEW_PRIVS`), never inherited from a checkpoint; no CRI-O in
   this deployment. No action taken.
4. **UK AI Security Institute "SandboxEscapeBench" (March 2026).**
   Frontier agents (GPT-5 and peers) escaped vanilla Docker containers
   ~50% of the time in 10 minutes; report notes sandboxing as "not
   keeping up" with capability scaling. Context for the cage work, not
   a technique to implement.
5. **aura research "Awesome-Seccomp Pitfalls" (GitHub).** Notes that
   "default-deny + 7 named blocks is a deny-list disguise" and that
   tests should cover ptrace, process_vm_*, bpf, userfaultfd, etc.
   Validates this wave's positive-allowlist + kill-tier test approach
   (all named classes are covered in
   `tests/test_sandbox_seccomp_cage.py`). Not opened; snippet-level
   note only.
