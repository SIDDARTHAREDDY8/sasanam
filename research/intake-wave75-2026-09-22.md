## What the intake establishes (load-bearing for the wave-75 design)

### 1. "Propose, don't write" is the independently-arrived shape for policy authorship — CONFIRMED
The strikersam governance README independently reached the identical
core construction this wave implements: **no endpoint rewrites the
live policy file**; policy change is propose → validate → review →
merge, with "who changed the rules" answerable from the audit trail.
The wave-75 `GovernedPolicyStore` mirrors it one level deeper:
propose → approve → apply, where `apply()` builds the live engine from
the stored artifact (not a file reread), so there is no reload path
for a compromised process to abuse.

### 2. Baseline can be tightened but never loosened from the dashboard — ADOPTED as the nuclear rule's twin
The same README refuses any proposal that removes a baseline
deny/require_approval pattern before any branch or PR is created. This
is the same instinct as the wave-75 nuclear rule: the *safety-critical
half* of the rule set should face asymmetric friction. Difference:
their refusal is static (baseline tags); ours is tiered by
environment, so dev/test/staging stay fast while production requires
two distinct human keys. Both designs treat loosening as the
"silently disable the controls" move.

### 3. Causality-chain audit, not "file changed" — CONFIRMED as the record shape
The rubennati schema (actor, initiated_via, agent, model, executor,
credential, approver, previous/new version) and the APM lock-file
pipeline (authorization + history + point-in-time state) converge on
the wave-75 record shape: authorship token (who + which key), canonical
digest over enforced meaning (what actually changed), structured diff
(what it means), parent-token chaining (what it follows), and a
point-in-time `policy_hash` in every audit decision record.

### 4. Two-person rule: two PEOPLE (keys), not two actions by one — CONFIRMED from PAL doctrine
PAL two-man-rule doctrine repeatedly counts **distinct individuals**,
never distinct actions by one individual: two keys spaced so one person
cannot reach both, sealed authenticators in a two-lock safe. The
wave-75 nuclear rule counts distinct roster KEYS (Ed25519 identities),
and the same-key-twice probe refuses a second signature from the
author's key. One person holding two keys is the PAL-equivalent of one
person reaching both keys — the spacing (distinct keys) is the whole
point.

### 5. Non-punitive, confidential near-miss reporting is what makes near-misses reportable — CONFIRMED as the ASRS framing
ASRS's load-bearing properties: voluntary, confidential,
de-identified, non-punitive; run by an independent third party (NASA),
not the enforcement body (FAA); genesis was a near-miss that had **no
channel** and was therefore followed, six weeks later, by the same
misunderstanding killing 92. The wave-75 ASRS write-up imports this
framing into agent governance: findings, residuals, and boundaries are
reported as blameless near-misses — "what almost happened, and what
changed" — because punishment-based disclosure drives exactly the
silence that defeats the system. Note: the wave-75 write-up is
docs/process only, not a new reporting mechanism; the intake supports
the framing, not a feature.

### 6. The "changed the rules" risk is live in the market — corroborated
The Moltbook case (unilateral, retroactive ToS change days after
acquisition) is the commercial shape of the threat wave-75 exists to
defeat: whoever controls the rule substrate can change the rules
retroactively. Our answer is structural — the substrate owner cannot
silently mutate the governed rules because there is no silent path —
not contractual.
