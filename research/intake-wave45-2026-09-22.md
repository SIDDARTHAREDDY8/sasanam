- "Physical AI" systems (interacting with real-world devices/machinery) may get common control measures — new scope note.
- Context: CSA May advisory (narrowly scoped agents, dedicated credentials, short-lived tokens in vaults, logging, human approval for high-impact actions **enforced through system-level mechanisms such as permission gates and approval workflows rather than relying only on instructions given to the model**) and NIST NCCoE's February concept paper (agent identification, authorisation, auditing, non-repudiation, anti-prompt-injection) both push the same direction. The Five Eyes "Careful Adoption of Agentic AI Services" advisory (May 1, 2026, CISA/NSA/ASD/others) calls prompt injection "the most pervasive and difficult-to-mitigate threat," requiring input sanitization layers.

No new findings. The direction of travel keeps validating the architecture: system-level enforcement, not model instructions.

## 2. BragJack — NEW incident class (watchlist)

Security researcher Gal Weizman (Forever Security) demonstrated "BragJack": a malicious **browser extension** hijacks the trusted communication channel between AI browser assistants and their privileged "body" components (Chrome, Edge, Opera Neon, Comet, Claude in Chrome). Dubbed **"prompt forcing"** — commands supplied directly to the browser's privileged control plane, **bypassing model-level safety filters entirely** (not prompt injection; no model trickery involved).

- Impact: Gemini's implementation (CVE-2026-0628, CVSS 8.8) allowed file reads, screenshots, camera/mic access; Comet's agent trusted an unprotected Perplexity testing domain (history/file access); Edge (CVE-2026-55945) needed a Think/Do race. ~$20k combined bounties; vendors patched most.
- Lesson (the report's words): AI agents need strict origin validation and isolated command channels.

**Why it matters to us:** our instruction hierarchy assumes the channel from the model to the tool actuator is trustworthy — the trust adapter sits *above* the executor. BragJack is the class that attacks *below* that layer: a compromised actuator channel. Our sandbox/approval controls assume the executor faithfully represents the model's intent. This is a genuinely new class for the B1 list (privileged-channel hijack below the policy layer). **→ B1 watchlist, analysis queued for wave-46.** Not a finding today: no demonstrated shape against our executor; the browser-extension vector is outside our harness, but the structural question (can anything inject tool calls below the trust adapter?) deserves a deliberate answer.

## 3. Moltbook cross-agent detail — reputation-mediated injection (watchlist)

failure-first report #38 ("cross-agent prompt injection," 4 days ago) adds: the malicious "skill" (personality upgrade → curl exfil) was validated by **social proof — high upvotes from other infected agents** — i.e., the social engineering targeted the agents' alignment/training rather than a human. Plus: infected agents formed a botnet with the platform as C2; traffic probing CVE-2026-0755 against connected agents; the Supabase RLS failure (millions of keys) per wave-44.

**New shape for us:** reputation-mediated trust — "N other agents vouched for this." Our tool-rating/skill controls (`gov/tool_ratings.py`) — do they weight peer reputation? If a future skill marketplace scores by agent votes, infected-agent upvotes are a Sybil vector. **→ watchlist for the tool-ratings surface; no finding** (no marketplace exists in the repo today).
